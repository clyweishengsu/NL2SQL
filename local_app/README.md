# 自然语言转 SQL · 本地工作台

这是基于原有 HTML 页面视觉样式重建的**真实可运行版**。当前界面以 MySQL 为入口，没有预置问句或答案。生成 SQL 需要用户自行配置可调用的 OpenAI 兼容模型，查询结果直接来自用户连接的 MySQL 数据库。

## 启动

- Windows：双击工作区根目录的 `启动本地版.bat`。
- 命令行：`py -3.9 local_app/server.py`，然后打开 `http://127.0.0.1:8765/`。
- 当前打包版已在 Windows Python 3.9 上验证；MySQL 驱动和 SQL 解析器已放在 `local_app/vendor/`，启动时无须另行安装。使用其他 Python 版本时，打包的原生加密组件可能不兼容。

服务仅绑定 `127.0.0.1`。关闭命令行窗口或按 Ctrl+C 即停止服务。

## 发布无需 Python 的 Windows 便携版

开发机安装 PyInstaller 后，在工作区根目录运行 `powershell -ExecutionPolicy Bypass -File .\build-windows-portable.ps1`。
脚本会生成 `dist\NL2SQL-Workbench-Windows-x64.zip`。最终用户需要完整解压该目录后双击 EXE，
无需安装 Python、Node.js 或额外数据库驱动。便携版的用户配置保存在
`%LOCALAPPDATA%\NL2SQLWorkbench\data`，不会包含开发机 `local_app\data` 中的配置。

如果 MySQL 返回 **1045**，说明服务器拒绝这个账号登录。请用相同的主机、端口、用户名和密码在当前电脑的 MySQL 客户端验证；若仍失败，请让数据库管理员检查账号允许登录的来源地址。不要在聊天中发送密码。

## 试用流程

1. 在「数据库与库表导入」连接 MySQL。请使用只有 SELECT 权限的专用账号。
2. 系统读取当前数据库的表名、字段、主键和原生注释。在同一菜单搜索、勾选并**保存**要参与问数的表。读取的是库表结构，不复制业务数据行。未保存的表选择不会生效；未纳入的表不会进入模型上下文，也不能在 SQL 中查询。跨表查询时，请一并纳入所需的关联中间表。
3. 保存库表范围后，「元数据配置」菜单才可进入。页面中的配置向导会依次引导完成表业务信息、核心字段、表关系和明细查询默认设置。没有声明外键时可手工添加关系。可以标记敏感字段；标记后不进入模型上下文，也无法被查询。原生表注释会在加载时预填空白业务名，保存后生效。
4. 在「模型配置」填写 Base URL、模型名称和 API Key，再点击「测试真实模型调用」。输出 Token 上限默认 8192；`hy4-preview` 如果提示输出截断，可调到 16384。思考模型请求超时默认 120 秒。本地 Ollama 等兼容服务可不填 Key。
5. 到「问数台」提问。点击「生成 SQL」会先检查数据库是否连接、是否已导入库表；通过后再调用模型。模型需要澄清指标或字段时可返回 2～4 个可点击选项。审阅生成的 SQL，点击「执行只读查询」。SQL 可以在执行前编辑。

配置模型后，表信息和字段描述页可请求**真实模型**生成草稿。草稿只填入当前编辑框，需人工核对并手动保存；不会预置答案或自动写入数据库。

元数据页的完成度分四级：缺少表业务名、表解释或核心字段时为「存在风险」；必要项齐全后为「可问数」；补充用途、至少 5 个常用字段和明细默认展示字段后为「基本完成」；全部非敏感字段、唯一标识和默认排序均就绪后为「完整配置」。原生注释预填计入当前草稿，保存后才用于问数。

每张表可在「明细查询」页配置实体唯一字段、默认展示字段、默认时间字段、默认排序、默认返回条数和常用筛选字段。用户只说“查看最近一个月的项目明细”时，模型会在用户没有明确指定的部分使用这些默认值；用户问题中的明确要求优先。

## 当前范围

- 已实现：MySQL 连接、真实 Schema 读取与库表范围筛选、分步元数据向导、分层完成度、表/字段/关系元数据编辑、明细查询默认设置、原生注释回填、真实模型草稿、动态上下文、真实模型请求、可选项澄清、按方言解析 SQL、只读校验与执行、结果表格。后端保留 CSV/SQLite 支持，但当前界面不显示文件导入入口。
- 数据库查询方言为 MySQL 和 SQLite。PostgreSQL 等需要后续增加驱动及执行适配层。
- 模型使用 OpenAI 兼容的 `chat/completions` 协议。服务商协议不兼容时无法调用。
- 提问时，问题、相关表字段结构和填写的业务说明会发送到你配置的模型服务；执行查询得到的数据行不会发送给模型。使用云端模型前，请确认这些元数据允许传给该服务。
- 模型 Key 和 MySQL 密码仅在当前服务进程内存中，**不写入磁盘**；MySQL 地址、库名、账号、已选表和业务描述保存在 `local_app/data/`。此目录由应用自动创建。重启服务后需要重新输入 MySQL 密码。
- 每次查询最多返回 200 行，执行限时 8 秒。模型生成的置信度只是模型自评，需通过实际结果判断正确性。
- 当前为单机试用版，尚未实现多用户登录和数据库行级权限。请在个人可信电脑上运行，并只导入允许在本地处理的数据。

## 验证

执行 `py -3.9 -m unittest discover -s local_app/tests -v` 运行后端检查。
